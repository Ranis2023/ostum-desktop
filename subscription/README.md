# Проверка подписки OSTUM Pro

[English operator guide](README.en.md)

В OSTUM 5.2 первая подтверждённая подписка даёт бессрочный Pro. Приложение генерирует QR локально, телефон открывает личный чат выделенного бота. Изолированная рабочая станция принимает подписанный файл с носителя. [Бот OSTUM](https://t.me/rangoostum_bot) · [Канал Раниса](https://t.me/ranisgaliaskarov) · [Проверка подписки Telegram](https://core.telegram.org/bots/api#getchatmember)

## Настройка владельцем

1. Добавьте **@rangoostum_bot** в администраторы **@ranisgaliaskarov**. В BotFather откройте **/mybots → @rangoostum_bot → API Token**.
2. В учётной записи Windows, где хранится ключ издателя, откройте **Configure.cmd**. Вставьте токен в скрытое поле. Для выделенного бота оставьте флажок запуска на этом компьютере. При сохранении мастер обращается к Telegram, запускает обработчик и при выбранном флажке добавляет его в автозапуск текущего пользователя. Кнопка повторной проверки использует сохранённый токен. Токен и закрытый ключ хранятся вне репозитория под защитой Windows DPAPI.
3. Для выдачи новых файлов нужны интернет на стороне издателя и работающий обработчик. Уже активированные ПК работают автономно независимо от доступности обработчика.

Для проверки и запуска из Windows PowerShell используйте команды из каталога проекта.

```powershell
.\subscription\Issuer.ps1 -Mode Check
.\subscription\Issuer.ps1 -Mode Run
```

`Check` проверяет токен, имя бота, канал и права администратора. `Run` обслуживает только настроенный отдельный бот и проверяет отсутствие подключённого webhook. После прерванной настройки `Resume` повторяет проверку с уже зашифрованным токеном. В `%LocalAppData%\OSTUM-Subscription-Issuer` находятся отметки времени `last-poll.utc` и `last-issue.utc`. Одна относится к успешному опросу Telegram, вторая — к успешной доставке файла. Содержимое файлов пользователей в эти отметки не попадает.

Если выделенный бот позднее будет перенесён в существующий сервис, выберите режим интеграции в мастере. Существующий обработчик Telegram может передавать полученное и проверенное им обновление на стандартный ввод `Issuer.ps1 -Mode HandleUpdate` в доверенной среде издателя. Режим принимает запросы с префиксом p2_ или p_, соответствующие команды `/start` и повторные проверки. Прямой приём обновлений произвольных клиентов в этот интерфейс должен быть закрыт.

## Автономное подтверждение

Файл содержит случайный идентификатор установки, время выдачи, тип доступа и подпись RSA-SHA256. OSTUM проверяет подпись встроенным открытым ключом, сверяет устройство и формат подтверждения. Документы, пути, переписка, телефон и имя пользователя в файл не включаются. Telegram видит обычные данные взаимодействия с ботом. Для полностью изолированного ПК запрос и файл можно переносить вручную. После первой проверки сервис сохраняет защищённую запись под непрозрачным именем в каталоге subscribers учётной записи издателя. Записи не содержат открытого Telegram ID. При повторном запросе из того же личного аккаунта сервис выдаёт подписанный файл на новый код без повторной проверки подписки. Сохраняйте этот каталог вместе с ключом издателя в резервной копии. Прежний бот 5.1 такого реестра не вёл.

Клиент 5.2 отправляет префикс p2_ и проверяет подпись OP2 с признаком permanent. Для запросов с префиксом p_ сервис выдаёт OP1, совместимый с 5.1. В 5.2 подлинный OP1 для той же установки считается доказательством уже пройденной проверки, включая исторические подтверждения. Редактирование срока или кода устройства нарушает подпись. В USB-комплект попадает только открытый ключ.

`issuer-public.xml` содержит только открытый ключ. Его парный закрытый ключ защищён DPAPI учётной записи издателя. Резервное копирование этой учётной записи и её DPAPI-ключей важно для дальнейшей выдачи файлов. Сборки сторонних разработчиков со своим ботом требуют собственной пары ключей и собственных идентификаторов бота и канала. Для свежего проекта режим `Initialize` генерирует новую пару и прекращает работу, если уже присутствующий открытый ключ не соответствует хранилищу издателя.
