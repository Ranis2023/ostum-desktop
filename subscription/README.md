# Проверка подписки OSTUM Pro

Пользователь подписывается на канал и открывает **Рабочие пространства Pro → Проверить подписку в Telegram**. Telegram передаёт боту код установки через команду `/start`. Бот проверяет собственные права администратора и текущий статус отправителя через `getChatMember`. Он выдаёт подписанный файл в личном чате подписчика. При отказе показывает кнопку подписки и повторной проверки. [Бот OSTUM](https://t.me/rangoostum_bot) · [Канал разработчика](https://t.me/ranisgaliaskarov) · [Метод Telegram](https://core.telegram.org/bots/api#getchatmember) · [Ссылки для запуска ботов](https://core.telegram.org/bots/features#deep-linking)

## Настройка владельцем

1. Добавьте **@rangoostum_bot** в администраторы **@ranisgaliaskarov**. В BotFather откройте **/mybots → @rangoostum_bot → API Token**.
2. В учётной записи Windows, где хранится ключ издателя, откройте **Configure.cmd**. Вставьте токен в скрытое поле. Для выделенного бота оставьте флажок запуска на этом компьютере. При сохранении мастер обращается к Telegram, запускает обработчик и при выбранном флажке добавляет его в автозапуск текущего пользователя. Кнопка повторной проверки использует сохранённый токен. Токен и закрытый ключ хранятся вне репозитория под защитой Windows DPAPI.
3. Для выдачи и продления подтверждений компьютер издателя должен иметь интернет, а обработчик должен работать. Короткий перерыв в работе обработчика допускает доставку сообщений из очереди Telegram. На стороне пользователя уже выданный файл действует до своей даты окончания. Сроки хранения обновлений описаны в [Telegram Bot API](https://core.telegram.org/bots/api#getting-updates).

Для проверки и запуска из Windows PowerShell используйте команды из каталога проекта.

```powershell
.\subscription\Issuer.ps1 -Mode Check
.\subscription\Issuer.ps1 -Mode Run
```

`Check` проверяет токен, имя бота, канал и права администратора. `Run` обслуживает только настроенный отдельный бот и проверяет отсутствие подключённого webhook. После прерванной настройки `Resume` повторяет проверку с уже зашифрованным токеном. В `%LocalAppData%\OSTUM-Subscription-Issuer` находятся отметки времени `last-poll.utc` и `last-issue.utc`. Одна относится к успешному опросу Telegram, вторая — к успешной доставке файла. Содержимое файлов пользователей в эти отметки не попадает.

Если выделенный бот позднее будет перенесён в существующий сервис, выберите режим интеграции в мастере. Существующий обработчик Telegram может передавать полученное и проверенное им обновление на стандартный ввод `Issuer.ps1 -Mode HandleUpdate` в доверенной среде издателя. Режим принимает только запросы вида `p_…`, соответствующие команды `/start` и повторные проверки. Прямой приём обновлений произвольных клиентов в этот интерфейс должен быть закрыт.

## Автономное подтверждение

Файл содержит случайный идентификатор установки, время выдачи, срок окончания и подпись RSA-SHA256. OSTUM проверяет подпись встроенным открытым ключом, сверяет устройство и срок. Документы, пути, переписка, телефон и имя пользователя в файл не включаются. Telegram видит обычные данные взаимодействия с ботом. Для полностью изолированного ПК запрос и файл можно переносить вручную. После отписки текущий файл действует до окончания семи дней, а следующий запрос требует действующей подписки. Ранее опубликованные версии OSTUM сохраняют прежние условия доступа.

`issuer-public.xml` содержит только открытый ключ. Его парный закрытый ключ защищён DPAPI учётной записи издателя. Резервное копирование этой учётной записи и её DPAPI-ключей важно для дальнейшей выдачи файлов. Сборки сторонних разработчиков со своим ботом требуют собственной пары ключей и собственных идентификаторов бота и канала. Для свежего проекта режим `Initialize` генерирует новую пару и прекращает работу, если уже присутствующий открытый ключ не соответствует хранилищу издателя.
