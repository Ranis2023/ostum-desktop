# Корпоративная установка OSTUM Desktop 5.0

## Изолированная рабочая станция

1. На машине подготовки соберите или получите полный образ. Проверьте контрольную сумму образа через Get-FileHash. Сверьте её с суммой, переданной по доверенному каналу вашей организации. У выпуска 5.0.0 отсутствует подпись издателя.
2. Перенесите ISO на целевую станцию, подключите его в Проводнике и запустите Ostum-Desktop-Setup.exe. Для установки под текущей учётной записью из командной строки доступны флаги `--quiet --offline --no-launch`. Языковая модель, диктовка, рисование, офисные редакторы и обучение используют файлы комплекта.
3. Администратор создаёт каталог `%ProgramData%\OSTUM`, копирует туда пример как `policy.json` и указывает реальные папки и группы Windows. Обычным пользователям нужны только чтение политики и соответствующий доступ к проектам. Права на запись политики и её родительской папки оставьте администраторам. [Пример конфигурации](company-policy.example.json)
4. Настройте системные ограничения исходящих соединений, доступ к съёмным носителям, резервное копирование, шифрование и правила доступа к рабочей станции согласно требованиям организации. Облачный клиент синхронизации или сторонний процесс может читать данные независимо от режима OSTUM. Для строгой изоляции выбирайте локальный диск вне синхронизируемых папок.

## Права проекта

| Параметр | Действие |
| --- | --- |
| Managed | Включает корпоративный режим и отключает внешние сетевые функции приложения, включая поиск, загрузку весов, проверку выпусков и кнопку перехода в Telegram. |
| LocalAI | Разрешает локальный вывод. При false компания может оставить только редактирование документов. |
| Training | Общее разрешение на обучение. Дополнительно требуется право Training у проекта. |
| Projects, Groups | Полные пути к папкам проекта и названия локальных или доменных групп Windows. Пустой массив Groups разрешает работу пользователям с доступом к папке. Для вложенных проектов действуют ограничения всех охватывающих правил. |
| Analysis | Разрешает отправить в Zarum вопрос и фрагмент, явно выбранный в редакторе. Действие фиксируется в журнале. |
| InternalShares | Разрешает UNC-пути внутри указанных папок. Windows проверяет доступ к файловому серверу. Для полностью отключённой станции значение false. |
| ImportedModels, ModelFolders | Разрешает подключить GGUF только из одобренных каталогов. Администратор может выдавать пользователям чтение проверенной библиотеки. |
| ChatHistory | Разрешает хранение обычных диалогов OSTUM. Рабочие запросы по выбранному фрагменту выполняются в окне проекта. |

## Где лежат данные

Рабочий файл сохраняется в его исходной папке. История редакций лежит рядом в `.ostum-versions`. Файлы адаптеров, отчёты с отложенными ответами и маркер активной версии находятся в `.ostum-training\<SID пользователя>` внутри проекта. Унаследованные NTFS-права определяют, кто может прочитать содержимое этих файлов через Windows. Для конфиденциального обучения выделите отдельную папку с раздельными NTFS-правами. Отзыв адаптера прекращает выбор этой версии при последующих запросах. Сроки хранения, архивирования и удаления исходников, отчётов, версий и резервных копий устанавливает организация.

Журнал `%LocalAppData%\SferaAI\pro\operations.log` содержит время UTC, SID, название операции и SHA-256 идентификатора ресурса. Тексты договоров и ответов в журнал операций не записываются. Это локальный журнал пользователя. Если нужны доказуемая неизменяемость или централизованный аудит, их обеспечивает инфраструктура организации.

## Приёмка перед внедрением

На тестовой учётной записи отключите внешний маршрут. Откройте файл в папке «только редактор», измените один абзац, сохраните и восстановите версию. Проверьте отказ при запросе анализа и обучения. В проекте с разрешённым анализом выберите один абзац и запросите резюме. В учебном проекте обучите версию на вымышленных данных, просмотрите контрольные ответы, включите её, отзовите и повторите запрос. Проверьте сетевой журнал средствами организации и доступ из второй учётной записи. Правила отраслевой эксплуатации, обработки персональных данных и принятия решений проверяются отдельно при внедрении.
